# Events and Schedule

Event files are stored in `plugins/FioFishing/Events/`, with one `.yml` file per event. `settings.yml` controls the weekly schedule.

## Event IDs and types

Use a lowercase ID in `id`; the file name should describe that ID. Choose one of the available event types:

| Event ID | Value for `type` | Scoring criteria |
| --- | --- | --- |
| `most_fish_caught` | `MOST_FISH_CAUGHT` | Catch the highest number of fish. |
| `most_largest_fish_caught` | `MOST_LARGEST_FISH_CAUGHT` | Score for catching large fish. |
| `most_smallest_fish_caught` | `MOST_SMALLEST_FISH_CAUGHT` | Score for catching small fish. |
| `largest_fish_caught` | `LARGEST_FISH_CAUGHT` | Catch the largest fish. |
| `smallest_fish_caught` | `SMALLEST_FISH_CAUGHT` | Catch the smallest fish. |
| `most_rarity_fish_caught` | `MOST_RARITY_FISH_CAUGHT` | Catch the most fish of a selected rarity. |
| `most_junk_caught` | `MOST_JUNK_CAUGHT` | Catch the most junk. |
| `most_bait_used` | `MOST_BAIT_USED` | Use the most bait. |
| `most_specific_bait_used` | `MOST_SPECIFIC_BAIT_USED` | Use a specific bait the most. |
| `fishing_spree` | `FISHING_SPREE` | Maintain a fishing spree; this can speed up bite times. |

## Event file structure

```yaml
# This ID must match the ID in the weekly schedule.
id: most_fish_caught

settings:
  # Enable the event so it can be started or scheduled.
  enabled: true
  # Event type from the table above.
  type: MOST_FISH_CAUGHT
  # Rarity and fish/bait ID filters; [] means no restrictions.
  list-rarities: []
  match-fish-ids: []
  # Bite-speed multiplier; 1 is normal and higher values are faster.
  bite-speed-multiplier: 1.0
  soundsDuringEvent:
    # Minecraft sound played during the event.
    sound: MUSIC_DISC_CHIRP
    # Ticks between repeats; -1 plays only when the event starts.
    tickLoop: 3700
    volume: 1.0
    pitch: 1.0
    # Minecraft sound category, for example MASTER, MUSIC, RECORDS.
    category: MASTER
  requirements:
    player:
      # Minimum number of online players.
      enable: true
      value: 5
    region:
      inPlayer:
        # Requires WorldGuard and the region listed below.
        enable: false
        region:
          - fishing_dock
        # Minimum number of players in the region.
        value: 5

event:
  whenStarted:
    # Run actions when the event starts.
    enabled: true
    commands:
      - '[MESSAGE] <green>Event {eventName} has started!</green>'
  whenStopped:
    enabled: false
    commands: []

bossbar:
  # Color: BLUE, GREEN, PINK, PURPLE, RED, WHITE, YELLOW.
  colour: BLUE
  # %time% is the remaining time; {eventName} is the event name.
  message: '<aqua>Fishing Contest</aqua>: <white>%time%</white>'

rewards:
  participate:
    # Rewards for every player who joins the event.
    enable: false
    commands:
      - '[MONEY] 100'
  tier:
    commands:
      # Rewards for ranks 1, 2, 3, and other ranks (*).
      '1': ['[EXP_POINTS] 10']
      '2': ['[EXP_POINTS] 5']
      '*': []
```

## Event options

- `list-rarities` contains rarity IDs such as `common`, `rare`, or `'*'`. It applies to event types that filter by rarity.
- `match-fish-ids` accepts fish or bait IDs, depending on the event type; `'*'` means all. Use the same IDs as the fish and bait files.
- `sound` under `soundsDuringEvent` is a Minecraft sound name. `tickLoop: -1` plays it once at the start; other values are repeat intervals in ticks. Volume and pitch are numbers. Sound categories include `MASTER`, `MUSIC`, `RECORDS`, `PLAYERS`, and `AMBIENT`.
- Player requirements use a minimum player count. Region requirements need WorldGuard, region names, and a minimum player count.
- Bossbar colors accept `BLUE`, `GREEN`, `PINK`, `PURPLE`, `RED`, `WHITE`, or `YELLOW`.
- Reward tiers use rank keys such as `'1'`, `'2'`, and so on; `'*'` is the fallback for ranks without a specific key.

## Weekly schedule

Edit `Events/settings.yml`. Each day has `enable` and `list-events` values. Times use the server's local time zone.

```yaml
schedule:
  monday:
    # Set to false to disable an entire day.
    enable: true
    list-events:
      # Timed format: event_id;HH:mm-HH:mm
      - 'most_fish_caught;18:00-19:00'
      # Without a time range, the event runs for the whole day.
      - fishing_spree
  tuesday:
    enable: false
    list-events: []
```

Accepted day names are `monday`, `tuesday`, `wednesday`, `thursday`, `friday`, `saturday`, and `sunday`. Each scheduled event ID must match the `id` value in its event file.

## Action format

```yaml
commands:
  - '[CONSOLE] say Event finished'
  - '[MESSAGE] <green>Congratulations!</green>'
  - '[SOUND] BLOCK_NOTE_BLOCK_PLING 1 2'
  - '[TITLE] <gold>Winner!</gold>'
  - '[SUBTITLE] You received a reward'
  - '[MONEY] 100'
  - '[EXP_POINTS] 10'
  - '[EXP_LEVEL] 1'
  - '[ITEM] DIAMOND 1'
```

`[MONEY]` runs `eco give` and requires an economy plugin. `[ITEM]` gives a basic Minecraft material with an optional amount. `[CONSOLE]` commands run as the console; player actions are sent to the reward recipient. Text supports MiniMessage and event placeholders such as `{eventName}`.
